# Breaking Changes

> Журнал ломающих изменений API и контрактов между фронтом и backend.
> Никакие breaking changes не мержатся без записи в этом файле.

---

## Что считается breaking change

| Тип | Пример |
|-----|--------|
| Удалён endpoint | `DELETE /api/v1/tweets/{id}` → нет |
| Переименован endpoint | `/api/v1/me` → `/api/v1/users/me` |
| Изменился тип поля | `Tweet.likes: int` → `Tweet.likes_count: int` |
| Удалено поле в ответе | `User.bio` больше не возвращается |
| Изменено required-поле в запросе | `Register.username` теперь обязательно |
| Изменён формат ошибки | `{ "error": "..." }` → `{ "code": "...", "message": "..." }` |
| Изменена семантика 200 ответа | `204 No Content` вместо `200 { ok: true }` |
| Сдвинут код ответа | `401` вместо `403` для auth |
| Изменён формат токена / cookie | JWT payload поля переименованы |
| Удалена/переименована очередь / event | Kafka topic `tweet.created` → `tweets.created.v2` |

**НЕ breaking:** добавление нового nullable поля в ответ, добавление
optional поля в запрос, новый endpoint, новый код ошибки внутри уже
существующего формата.

---

## Policy

1. **Версионирование префиксом.** Все public endpoints под `/api/v{N}/`.
   Текущая major-версия: **v1**.
2. **Параллельная поддержка.** Когда выходит v2, v1 живёт минимум **2 фазы**
   (см. `/SOUL.md` § План развития). Удаление — отдельным релизом с
   объявлением за 30 дней.
3. **Deprecation header.** Старые endpoints возвращают
   `Deprecation: true` и `Sunset: <RFC 3339 date>` headers.
4. **Запись в этот файл — обязательна** до мержа PR с ломающим изменением.
5. **Миграционный гайд.** Для каждого breaking — минимальный snippet "было
   → стало" для клиентов.

## Журнал

### v1 (текущая) — 2025-06 → ...

Начальная стабильная версия. Эндпоинты: см. `docs/shared/API.md`.

Никаких breaking changes внутри v1 не вносилось.

---

### v2 (запланирована) — Фаза 3

Триггер выпуска v2: одно из ниже.

- [ ] Изменение схемы Tweet под media (несовместимое поле `media[]` →
      объект с типизированными ресурсами)
- [ ] Унификация формата ошибок (см. `docs/shared/ERRORS.md`)
- [ ] Notification payload изменения (Фаза 3, см. SOUL.md)

Пока ни один триггер не сработал — v2 не публикуется.

#### Шаблон записи для будущих изменений

```markdown
#### YYYY-MM-DD — <короткое название>

**PR:** #NNN  
**Endpoints / events:** `POST /api/v1/tweets`  
**Тип:** Изменение типа поля

**Было:**
\`\`\`json
{ "likes": 5 }
\`\`\`

**Стало:**
\`\`\`json
{ "likes_count": 5 }
\`\`\`

**Миграция клиента:**
- Читать `likes_count`. Поле `likes` будет удалено в v3.
- v1: оба поля присутствуют (alias).
- v2: только `likes_count`.

**Sunset v1 поля:** 2026-12-01
```

## Клиентский опыт

| Клиент | Что делать |
|--------|-----------|
| Flutter | Обновить модели в `packages/app_api/`. Тесты на десериализацию old/new payload. |
| Web | Sync OpenAPI → typed client. |
| iOS / Android | Аналогично — модели + DTO. |

Версия API возвращается в каждом ответе header'ом `X-API-Version: v1`.
Клиент логирует расхождение `X-API-Version` ≠ ожидаемой версии.
